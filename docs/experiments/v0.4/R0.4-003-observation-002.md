# R0.4-003 Observation 002

## Finding

Inspection of the v0.4 Fool sandbox implementation revealed an unintended
information-topology leak.

## Intended Boundary

Only the Fool should operate without inherited council knowledge.

Expected:

Researcher through Red Team:
- normal knowledge access

Fool:
- previous context restricted
- accumulated knowledge base restricted
- handoff context restricted

Editor through Librarian:
- normal knowledge access restored

## Actual Boundary

`KNOWLEDGE_CONTEXT` is constructed once before the agent loop.

During the Fool iteration the runtime executes:

    KNOWLEDGE_CONTEXT=""

Because this shared variable is not rebuilt after the Fool completes,
all subsequent agents inherit the empty knowledge context.

Actual behavior:

Researcher through Red Team:
- normal knowledge base

Fool:
- restricted knowledge base

Editor through Librarian:
- unintentionally restricted knowledge base

## Classification

Experimental confound.

## Consequence

The v0.4 provenance test does not represent clean Fool-only context isolation.

The observed failure to preserve Fool provenance through Editor synthesis
remains relevant, because the Fool artifact itself contained provenance
metadata and entered the synthesis handoff.

However, downstream reasoning may also have been affected by the accidental
loss of the accumulated knowledge base.

## Architectural Requirement

Sandbox restrictions must operate on agent-local context variables.

A sandbox must not mutate shared institutional context used by subsequent
agents.

## Proposed Fix

Create an agent-local copy of the accumulated knowledge context during each
agent iteration.

For example:

    AGENT_KNOWLEDGE_CONTEXT="$KNOWLEDGE_CONTEXT"

The Fool may then clear the local copy without modifying the shared knowledge
base.

## Status

Sandbox isolation: FAIL — boundary leaked downstream.

Provenance experiment: CONFOUNDED — rerun required after boundary repair.
