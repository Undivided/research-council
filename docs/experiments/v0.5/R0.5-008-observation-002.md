# R0.5-008 Observation 002

## Deterministic Concurrent-Resumer Validation

PASS.

R0.5-008 was tested with a deterministic interrupted run and two competing
resume processes.

## Initial Interrupted Run

The Council was interrupted while Historian was executing.

The logical run identity was:

    run_id: 20260911-090848

The durable state represented:

    run_status: interrupted
    current_agent: historian
    attempted_agents: 2
    completed_agents: 1

The completed Researcher retained its successful agent outcome.

Historian had been attempted but had not completed.

## First Resumer

The first resumer successfully acquired the per-run kernel-backed resume lock.

It changed the logical run state to:

    run_status: running
    reason: resumed_execution
    current_agent: historian

The deterministic model shim deliberately held Historian execution open while
the first resumer retained ownership of the run.

## Competing Resumer

While the first process held the lock, a second process attempted:

    --resume r0.5-008-concurrent-resumer-control 20260911-090848

The second process exited:

    75

with:

    ERROR: Another process already owns resumption of this run.

## Zero-Mutation Control

Immediately before and after the competing resumer attempt, the following were
measured.

The run-state SHA-256 was unchanged.

The durable counts remained:

    outcomes: 1 -> 1
    raw files: 3 -> 3
    analysis artifacts: 1 -> 1
    model invocations: 3 -> 3

The competing resumer therefore:

    did not invoke a model
    did not alter run state
    did not create an outcome
    did not create raw output
    did not create a promoted artifact
    did not perform an institutional action

The lock rejection occurred before Council execution mutation.

## Legitimate Resumer Completion

After the competing process was rejected, the first resumer was released.

The final durable state was:

    run_status: completed

    current_agent: null
    failed_agent: null

There were exactly eleven successful R0.5-004 outcomes.

No failed outcomes existed.

All outcomes and the run-state record shared:

    run_id: 20260911-090848

The final human-readable run record was created.

## Lock-File Semantics

The durable pathname:

    resume-20260911-090848.lock

remained on disk after execution.

A subsequent nonblocking `flock` on that pathname succeeded.

Therefore:

    lock file exists
    !=
    live process owns the resume lock

Live ownership is represented by the kernel lock associated with the open file
descriptor.

The pathname itself does not carry liveness semantics.

## Institutional Side Effects

The rejected competing resumer produced no duplicate institutional action.

## Limitation

R0.5-008 uses a local operating-system advisory lock.

It does not provide:

- distributed locking between hosts
- network leases
- queueing of competing resumers
- automatic retries
- automatic resume discovery
- serialization of unrelated runs
- generalized scheduler ownership

## Conclusion

R0.5-008 passes deterministic concurrent-resumer validation.

A logical interrupted run can have at most one active local resumer.

A competing resumer is rejected before model invocation or durable Council
mutation, while the legitimate resumer remains able to complete normally.
