# R0.5-001 First-Class Cognitive Provenance

## Question

Can cognitive provenance become a first-class system object rather than information that survives only through model-generated text?

## Context

Research Council v0.4 established that sandboxed cognition requires provenance.

The validated v0.4 pipeline demonstrated:

Fool
→ Editor
→ Judge
→ Archivist
→ Knowledge

while preserving the exploratory status of sandboxed material.

However, the provenance mechanism remains partly dependent on natural-language behavior.

The Fool report contains provenance metadata, and downstream cognitive functions are instructed to preserve its epistemic status.

This creates a remaining weakness:

The system knows provenance because agents read and repeat provenance.

The runtime itself does not yet manage provenance as an independent object.

## Hypothesis

Provenance should exist independently from report content.

A cognitive artifact should consist conceptually of:

    artifact
    ├── content
    └── provenance

The content may be transformed.

The provenance should remain traceable independently of that transformation.

## Proposed Minimal Object

For the first experiment, provenance should contain only fields required to describe the cognitive conditions of generation.

Example:

    artifact_id: fool-task-001-134843
    agent: fool
    environment: sandbox
    experiment: R0.5-001
    context_mode: clean
    epistemic_status: exploratory

Additional fields should not be added unless the experiment demonstrates a need for them.

## Proposed Storage Model

Initial implementation should use a sidecar provenance file.

Example:

    fool-task-001-134843.md
    fool-task-001-134843.provenance.yaml

The Markdown file contains cognitive output.

The YAML file contains machine-readable provenance.

The two form one cognitive artifact.

## Why a Sidecar

A sidecar allows provenance to:

- exist independently of model output
- be created deterministically by the runtime
- be inspected without parsing generated prose
- survive transformations without requiring verbatim copying
- be tested independently from reasoning quality

This is an experimental implementation, not yet a permanent storage architecture.

## Experiment

Generate a sandboxed Fool contribution.

Verify independently that:

1. the report is generated normally
2. a provenance sidecar is generated by the runtime
3. the sidecar correctly describes the Fool's generation conditions
4. downstream synthesis can reference the provenance object
5. provenance remains available even if downstream prose does not repeat it verbatim

## Control

The v0.4 validated provenance pipeline serves as the behavioral baseline.

v0.4:

    provenance embedded in report
    +
    downstream preservation contract

v0.5 experimental condition:

    report content
    +
    independent provenance object
    +
    downstream provenance awareness

## Success Criteria

PASS requires:

- provenance object created independently of model output
- provenance object associated with the correct cognitive artifact
- sandbox classification represented correctly
- downstream transformations do not destroy provenance availability
- institutional memory can distinguish exploratory from accepted material

## Failure Modes

Possible failures include:

- provenance object becomes detached from its artifact
- sidecar and report disagree
- downstream agents cannot associate provenance with content
- provenance is duplicated inconsistently
- runtime implementation becomes more complex without improving reliability

## Constraint

Do not build a general provenance framework before the minimal object is validated.

The purpose of R0.5-001 is to test whether first-class provenance improves architectural reliability.

## Principle

Content answers:

> What was said?

Provenance answers:

> Under what cognitive conditions was it produced?

A reliable cognitive institution requires both.

## Status

Experiment defined.

No runtime implementation yet.
