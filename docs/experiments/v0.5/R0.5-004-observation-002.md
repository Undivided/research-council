# R0.5-004 Observation 002

## Deterministic Runtime Validation

PASS.

R0.5-004 was tested with deterministic Ollama shims before real-model
validation.

The tests exercised distinct runtime layers rather than treating every failure
as the same state.

## Control A — Successful Promotion

The Researcher model invocation succeeded.

Its raw generation contained a valid R0.5-003 artifact boundary.

The outcome record stated:

    invocation_status: succeeded
    artifact_status: promoted
    agent_status: succeeded
    reason: success

Both raw and promoted artifact paths were explicitly recorded.

## Control B — Artifact-Boundary Rejection

The Historian model invocation succeeded and produced raw output.

The raw generation contained one opening artifact delimiter and no closing
delimiter.

The outcome record stated:

    invocation_status: succeeded
    artifact_status: rejected_at_boundary
    agent_status: failed
    reason: invalid_boundary_count

The raw artifact path was explicit.

The promoted artifact was explicitly:

    null

No Historian analysis artifact was created.

The failure therefore no longer has to be inferred from filesystem absence or
terminal output.

## Control C — Model Invocation Failure

The Researcher model process exited unsuccessfully before producing any model
content.

The outcome record stated:

    invocation_status: failed
    artifact_status: not_created
    agent_status: failed
    reason: model_invocation_failed
    raw_artifact: null
    promoted_artifact: null

Shell redirection created a zero-byte raw-path placeholder on disk, but because
no bytes of model emission existed, the durable runtime record correctly
represented the raw artifact as null.

## Control D — Judge Post-Promotion Failure

The Judge model invocation succeeded.

Its artifact passed R0.5-003 boundary validation and was promoted into
`analysis/`.

The promoted artifact intentionally omitted the required R0.5-002 disposition
token.

The outcome record stated:

    invocation_status: succeeded
    artifact_status: promoted
    agent_status: failed
    reason: invalid_judge_disposition

The raw artifact and promoted artifact both remained present.

The Council then terminated at Judge according to the existing runtime
behavior.

Nine outcome records existed: one for every agent actually attempted through
Judge.

This demonstrates that:

    artifact promotion
    !=
    successful completion of the agent operation

## Control E — Archivist Nonfatal Post-Promotion Failure

The Archivist model invocation succeeded.

Its artifact passed R0.5-003 boundary validation and was promoted into
`analysis/`.

The promoted artifact intentionally omitted the required:

    ARCHIVAL REPORT

marker.

The outcome record stated:

    invocation_status: succeeded
    artifact_status: promoted
    agent_status: failed
    reason: archivist_report_missing

No normal Archivist knowledge entry was created.

The existing runtime treats this Archivist validation failure as nonfatal.

The Librarian was subsequently attempted and its outcome stated:

    invocation_status: succeeded
    artifact_status: promoted
    agent_status: succeeded
    reason: success

The complete run produced:

    11 agent outcome records
    1 normal run record

Therefore:

    agent operation failure
    !=
    necessarily whole-run termination

The synthetic Fool disposition created earlier in the same run was preserved
under the experiment's evidence directory and removed from canonical
`knowledge/entries/`.

## State Model

The deterministic controls establish three independent runtime dimensions:

    invocation_status

        Did the model invocation itself succeed?

    artifact_status

        Did R0.5-003 validate and promote a cognitive artifact?

    agent_status

        Did the complete agent-specific runtime operation succeed?

Observed combinations included:

    succeeded / promoted / succeeded

    succeeded / rejected_at_boundary / failed

    failed / not_created / failed

    succeeded / promoted / failed

These states cannot be represented accurately by a single success/failure
flag.

## Failure Durability

Failure outcome records existed before terminating failure paths returned from
the runtime.

Therefore terminal output is no longer the sole durable source of the failure
reason.

Operational status values are runtime-owned.

Models do not choose:

    invocation_status
    artifact_status
    agent_status
    reason

No semantic interpretation of model prose is used to determine these values.

## R0.5-003 Compatibility

R0.5-003 artifact-boundary behavior remained unchanged.

Malformed output was preserved as raw evidence and prevented from promotion.

Successfully bounded output was promoted normally.

## R0.5-002 Compatibility

The deterministic Archivist control successfully passed through the existing
Judge disposition path before the later Archivist-specific failure.

R0.5-002 therefore remained functional on successful Judge operations.

## Qualification

R0.5-004 currently validates durable per-agent operational outcomes.

It does not yet introduce:

- retries
- automatic recovery
- workflow resumption
- scheduling
- aggregate run-status state
- explicit records for agents never attempted
- generalized event sourcing

Those are separate concerns.

## Conclusion

The deterministic R0.5-004 mechanism passes.

The runtime can durably distinguish:

    model invocation outcome
    artifact promotion outcome
    complete agent-operation outcome

without relying on missing files, model prose, or terminal logs to carry those
meanings.
