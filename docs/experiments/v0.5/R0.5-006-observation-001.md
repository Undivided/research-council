# R0.5-006 Observation 001

## Source Observation

R0.5-005 made whole-run state durable before the first agent invocation and
updated it throughout normal execution.

This solved the previous inability to distinguish:

    failed run
    completed run
    completed run with nonfatal agent failure

However, the state machine currently depends on normal runtime control flow to
reach a terminal state.

If the process terminates outside those paths, the last durable record may
remain:

    run_status: running
    reason: in_progress

## Finding

The system can now remember that a run exists before it finishes.

It cannot yet always distinguish:

    run currently executing

from:

    run stopped unexpectedly while marked running

## Implication

A future recovery or resumption mechanism must not begin by guessing whether a
persisted running state is actually live.

Catchable interruption should therefore become first-class durable run state
before retry or resume behavior is introduced.

## Scope

R0.5-006 should add interruption-state durability only.

It should not yet attempt restart, resume, replay, or automatic recovery.
