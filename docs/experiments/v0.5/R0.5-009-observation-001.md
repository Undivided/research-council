# R0.5-009 Observation 001

## Source Inspection Target

R0.5 currently has durable per-agent outcomes, whole-run state, interruption
handling, resumability, and exclusive local resume ownership.

The remaining terminal durability risk is multi-file publication ordering.

The critical source question is:

    In what exact order are the final successful agent outcome,
    completed run state, and final run record persisted?

Before implementation, the terminalization section of `run-council.sh` must be
inspected.

No mechanism should be selected until the actual write ordering and helper
functions are identified.

## Required Invariant

The canonical terminal run state must be the publication point.

If a reader can observe:

    run_status: completed

then every durable object required by completed-state semantics must already
exist and be complete.

This implies a likely design direction of:

    prepare prerequisite terminal artifacts
        ↓
    make them durable
        ↓
    atomically publish terminal whole-run state last

The exact implementation remains pending source inspection.
