# R0.5-002 Durable Epistemic Disposition

## Question

Can the Council preserve the epistemic disposition of significant cognitive
artifacts across the Archivist → durable-memory boundary without depending on
natural-language inference?

## Motivation

R0.5-001 demonstrated that first-class provenance can be:

- created independently of model output
- associated with the correct artifact
- classified as sandboxed/exploratory
- transported downstream

However, the final success criterion was not demonstrated.

The Editor explicitly distinguished Fool material as exploratory/sandboxed, but
the explicitly sandboxed hypotheses disappeared from the Archivist report.

No durable record showed whether that material was:

- deliberately rejected
- intentionally withheld from promotion
- deferred
- lost during summarization
- ignored for some unrelated reason

Therefore:

    absence from memory
    !=
    evidence of epistemic disposition

## Hypothesis

If epistemic status and disposition are represented as system-owned metadata at
the durable-memory boundary, institutional memory can preserve an artifact's
epistemic status separately from what the institution did with that artifact,
without relying on model prose to preserve the distinction.

## Experimental Principle

The model may write the thought.

The system owns the provenance and disposition record.

## Baseline

Current v0.5 behavior:

    Fool artifact
    +
    first-class provenance sidecar
    ->
    Editor synthesis
    ->
    Judge evaluation
    ->
    Archivist report
    ->
    knowledge entry

Observed failure:

    exploratory classification exists at Editor
    ->
    explicitly sandboxed Fool material disappears at Archivist
    ->
    no durable disposition record remains

## Experimental Condition

Preserve a minimal system-owned disposition record across the durable-memory
boundary.

For this experiment, preserve two separate dimensions:

    epistemic_status
    disposition

Do not collapse them into one label.

Epistemic status describes the cognitive status of the artifact.

Institutional disposition describes what the institution did with it.

For example, an exploratory artifact may legitimately be admitted to durable
memory while remaining exploratory:

    epistemic_status: exploratory
    disposition: accepted_into_memory

Admission to memory must not erase or upgrade the artifact's epistemic status.

Do not create a general epistemic-status or disposition framework.

## Minimal Record

The exact storage format may be determined during implementation, but the
minimum machine-readable information is:

    artifact_id
    epistemic_status
    disposition

The record must remain associated with the artifact it describes.

For the Fool specimen:

    epistemic_status: exploratory

If the institution admits that artifact to durable memory:

    disposition: accepted_into_memory

Disposition must state what the institution actually did with the artifact
rather than requiring future readers to infer intent from absence.

## Required Sequence

    cognitive artifact created
    ->
    provenance validated
    ->
    epistemic status known
    ->
    institutional adjudication
    ->
    disposition recorded
    ->
    durable memory written

The disposition record must not be created before the relevant artifact exists
and passes artifact-admission checks.

## Causal Control

R0.5-001 showed that role identity and Editor instructions can independently
cause the word "exploratory" to appear.

Therefore natural-language labels are not sufficient evidence.

The experimental test must distinguish metadata-driven behavior from
role-driven inference.

At minimum:

Experimental condition:

    provenance sidecar present
    +
    embedded exploratory prose not required

Control condition:

    provenance sidecar absent
    +
    role identity/prose still available

A durable exploratory classification must not be credited to first-class
provenance if the same classification occurs without the provenance object.

## Success Criteria

PASS requires all of the following:

- exploratory status remains machine-readable at the durable-memory boundary
- institutional disposition is separately machine-readable from epistemic status
- each status remains associated with the correct artifact
- significant exploratory material cannot silently disappear without a
  recorded disposition
- the distinction does not depend solely on natural-language labels
- the provenance-present condition produces an observable result that the
  no-provenance control does not
- future institutional retrieval can determine both the artifact's epistemic
  status and what the institution did with it without inferring intent from
  absence

## Failure Modes

Possible failures include:

- exploratory material disappears without disposition
- epistemic status and institutional disposition become conflated
- status becomes detached from its artifact
- model prose overrides system-owned status
- role identity reproduces the same result without provenance
- the Archivist invents disposition not supported by system state
- metadata is stored but unavailable to future institutional retrieval
- implementation expands into an unnecessary general provenance framework

## Constraints

Do not redesign the entire memory system.

Do not add taxonomy beyond what the experiment requires.

Do not infer rejection from omission.

Do not allow a model to promote its own exploratory artifact merely by changing
its wording.

Do not modify the result of R0.5-001.

R0.5-002 exists because R0.5-001 did not pass.

## Architectural Principle

A cognitive institution should remember not only what survived.

It should preserve enough evidence to know what happened to significant
material that did not.

## Status

Implemented and validated at the runtime and durable-memory level.

See the Implementation Amendment and Experimental Result below.

## Implementation Amendment — Clean Runtime Baseline

Before runtime implementation of R0.5-002, the experimental provenance-sidecar
runtime introduced during R0.5-001 was removed from the active Council runner.

The historical result of R0.5-001 is unchanged.

R0.5-002 therefore tests durable epistemic disposition from a clean runtime
baseline without restoring the general provenance-sidecar transport mechanism.

For the Fool specimen, the runtime owns:

    artifact_id
    epistemic_status: exploratory

These values are assigned only after the Fool artifact exists and passes the
existing artifact-output checks.

The Judge receives the actual Fool artifact and performs institutional
adjudication. The Judge may select only the disposition; it does not control
artifact identity or epistemic status.

The runtime validates the Judge's disposition and writes the durable record.

Revised experimental sequence:

    cognitive artifact created
    ->
    artifact output validated
    ->
    system-owned epistemic status assigned
    ->
    institutional adjudication
    ->
    disposition validated
    ->
    disposition record written to durable memory

For this implementation, the causal comparison is:

Experimental condition:

    system-owned artifact/status state present
    +
    constrained institutional disposition
    +
    durable machine-readable record

Control condition:

    no system-owned artifact/status state
    +
    role identity and natural-language prose remain available

A natural-language use of the word "exploratory" is not evidence that the
system preserved epistemic status.

No disposition may be inferred from omission by the Editor, Judge, Archivist,
or durable-memory output.

If the Judge fails to provide a valid disposition, the run fails explicitly
rather than silently assigning one.

## Experimental Result

PASS — runtime and durable-memory mechanism validated.

See:

    R0.5-002-observation-001.md

A system-owned artifact/status record produced durable machine-readable
epistemic status and institutional disposition. A clean-baseline causal control
reproduced natural-language exploratory/sandboxed classification but produced
no disposition record.

The mechanism was validated with deterministic synthetic model outputs to
isolate runtime behavior from model variance.
