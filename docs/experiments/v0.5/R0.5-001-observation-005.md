# R0.5-001 Observation 005

## Finding

A quota-induced model invocation failure exposed a runtime integrity defect.

During the final institutional-memory verification run, the cloud model
returned HTTP 429 errors beginning with the Skeptic invocation.

The runtime continued processing subsequent cognitive functions.

## Observed Behavior

Successful model outputs before quota exhaustion:

- Researcher: nonempty
- Historian: nonempty
- Philosopher: nonempty
- Strategist: nonempty

Failed model outputs after quota exhaustion:

- Skeptic: 0 bytes
- Red Team: 0 bytes
- Fool: 0 bytes
- Editor: 0 bytes
- Judge: 0 bytes
- Archivist: 0 bytes
- Librarian: 0 bytes

Despite the Fool model output being empty, the runtime generated a
machine-readable provenance sidecar for it.

Therefore the system recorded provenance for an attempted cognitive event
that did not successfully produce a cognitive artifact.

## Interpretation

First-class provenance requires a stronger artifact-admission boundary.

A runtime invocation attempt is not equivalent to a successfully generated
cognitive artifact.

Provenance describing an artifact must not be created until the runtime has
verified that the model invocation succeeded and that the artifact satisfies
minimum validity requirements.

Continuing the Council after a required cognitive function fails also changes
the intended information topology. A failed required function should therefore
halt the run rather than silently permit downstream processing.

## Experimental Status

This run is INVALID as a test of the remaining institutional-memory success
criterion because the model quota was exhausted before the Fool, Editor,
Judge, and Archivist completed successfully.

Institutional-memory distinction between exploratory and accepted material
therefore remains UNTESTED in this verification run.

The quota failure does not constitute failure of the provenance hypothesis.

## New Runtime Invariant

    attempted invocation
    !=
    admitted cognitive artifact

Required sequence:

    model invocation
    -> invocation success check
    -> artifact validity check
    -> artifact admission
    -> provenance creation
    -> downstream handoff

## Architectural Principle

The runtime must not record successful cognitive provenance for cognition
that did not successfully occur.
