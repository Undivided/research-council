# R0.5-005 Observation 001

## Source Observation

R0.5-004 deterministic testing produced two important contrasting cases.

### Judge Failure

The Judge:

    invocation_status: succeeded
    artifact_status: promoted
    agent_status: failed
    reason: invalid_judge_disposition

The process terminated at Judge.

Nine agent outcome records existed.

The Librarian and Archivist were not attempted.

No normal final Council run record was created.

The run failure therefore had to be reconstructed from:

    Judge outcome
    outcome count
    absent later-agent outcomes
    absent final run record
    terminal behavior

### Archivist Failure

The Archivist:

    invocation_status: succeeded
    artifact_status: promoted
    agent_status: failed
    reason: archivist_report_missing

The runtime continued.

The Librarian subsequently completed successfully.

Eleven outcome records existed.

A normal run record was created.

Therefore:

    agent_status: failed

does not itself determine whole-run state.

## Finding

R0.5-004 makes attempted-agent state explicit.

Whole-run state remains implicit.

The system currently knows whether execution is continuing or terminating, but
that fact is not independently represented as durable machine-readable state.

## Required Separation

The observations establish:

    agent outcome
    !=
    run outcome

and:

    agent not attempted
    !=
    agent failed

## Implication

A future evaluator, recovery mechanism, scheduler, or Council process should not
have to count files and infer control flow to discover whether a run completed.

Run state should become first-class before workflow recovery or retry behavior
is introduced.

## Scope

R0.5-005 should record whole-run state only.

It should not introduce recovery, retries, resumption, or orchestration
complexity.
