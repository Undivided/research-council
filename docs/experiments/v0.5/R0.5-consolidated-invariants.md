## Architectural Layers

### R0.5-002 — Durable Epistemic Disposition

The system durably distinguishes:

    epistemic_status

from:

    institutional disposition

The runtime owns artifact identity and epistemic status.

The Judge owns only the adjudicated disposition:

    accepted_into_memory
    rejected
    deferred
    withheld_from_memory

Disposition is not inferred from natural-language prose.

### R0.5-003 — Artifact Boundary Integrity

The system durably distinguishes:

    raw model emission

from:

    promoted cognitive artifact

Raw model output is preserved.

Only content inside exactly one valid Council artifact boundary is eligible for
promotion.

Malformed raw generation is preserved but not silently promoted.

### R0.5-004 — Agent Outcome Durability

The system durably distinguishes:

    model invocation state
    artifact promotion state
    complete agent-operation state

An attempted agent therefore has explicit operational state independent from
its natural-language output.

### R0.5-005 — Whole-Run State Durability

The system durably distinguishes:

    per-agent outcome

from:

    whole-run outcome

Run state explicitly represents:

    running
    completed
    failed

A completed workflow may still contain a nonfatal agent failure.

A failed run can identify how far execution progressed.

### R0.5-006 — Interrupted-Run Durability

The system durably distinguishes:

    active execution

from:

    catchably interrupted execution

Supported catchable signals include:

    SIGINT
    SIGTERM
    SIGHUP

An interruption produces:

    run_status: interrupted
    reason: process_interrupted

The in-flight agent is not falsely assigned a normal R0.5-004 failure outcome.

### R0.5-007 — Safe Run Resumption

The system durably distinguishes:

    new run

from:

    continuation of an interrupted run

Resumption:

- preserves the original run ID
- skips already-completed agents
- restarts the interrupted agent from its beginning
- preserves completed agent outcomes
- preserves completed promoted artifacts
- reconstructs process-local Council handoff state
- avoids duplicate Judge actions
- avoids duplicate Archivist actions

Run-start execution inputs are persisted:

    research question
    model identity
    Council agent roster and order
    full run-start knowledge context
    run-start retrieval context

Resumed execution uses these durable snapshots rather than rebuilding context
from mutated canonical memory.

## Run Counter Semantics

`attempted_agents` represents:

    furthest Council position entered in the logical run

It does not represent raw process-level invocation count.

This permits an interrupted agent to be retried without producing impossible
values such as:

    attempted_agents: 12

for an eleven-agent Council.

`completed_agents` represents successful durable agent outcomes for the run.

The invariant is:

    0 <= completed_agents <= attempted_agents <= total_agents

## Resume Safety Invariants

An initial R0.5-007 resume is permitted only when:

- the durable run state exists
- run ID matches
- project identity matches
- run status is interrupted
- no final run record already exists
- required durable input snapshots exist
- saved Council roster matches the current roster
- existing outcomes form a safe successful prefix
- durable counters agree with successful outcomes

The initial implementation intentionally fails closed when these conditions are
not satisfied.

## Historical Evidence

Historical provenance-sidecar experiment files remain preserved under the
original provenance experiment projects.

They are historical evidence and are not evidence that the current runtime
still produces provenance sidecars.

No R0.5-002 through R0.5-007 runtime project produced active provenance
sidecars after the sidecar mechanism was removed.

The first R0.5-007 resumption control predates the later run-start context
snapshot refinement.

Its missing:

    knowledge-context
    retrieval-context

files are therefore preserved as accurate historical evidence.

Later R0.5-007 controls use the final resumability snapshot schema.

## Canonical Memory Hygiene

Synthetic experimental disposition records and Archivist entries are copied
into their corresponding project evidence directories.

They are then removed from canonical:

    knowledge/entries/

Experimental validation therefore does not silently become normal institutional
memory.

## Current Limitations

The v0.5 architecture does not yet provide:

- automatic resumable-run discovery
- concurrent-resumer exclusion
- distributed leases
- generalized retries
- continuation inside model generation
- power-loss detection
- SIGKILL detection
- stale-running-run reconciliation
- rollback of arbitrary external side effects
- generalized event sourcing
- transactional multi-file state updates

## Architectural Principle

Absence should not carry institutional meaning.

Runtime-owned state should not be inferred from model prose.

Raw evidence should be preserved.

Promotion should require explicit structural validity.

Recovery should continue known work rather than silently replay completed
institutional history.

## Consolidated Result

R0.5-002 through R0.5-007 form a coherent durable-state stack.

The Council can now explicitly preserve:

    what the model emitted
    what became a cognitive artifact
    what happened institutionally to that artifact
    what happened operationally to each attempted agent
    what happened to the Council run as a whole
    whether the process was interrupted
    what execution inputs defined the logical run
    how an interrupted run may resume without replaying completed work

This document is the consolidation baseline for subsequent v0.5 experiments.
