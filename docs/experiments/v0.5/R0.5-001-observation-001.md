# R0.5-001 Observation 001

## Finding

The runtime successfully created an independent provenance sidecar for the
sandboxed Fool artifact.

## Provenance Object

The generated sidecar correctly recorded:

- artifact ID
- generating agent
- sandbox environment
- experiment identifier
- context mode
- epistemic status
- associated report filename

## Result

Provenance object creation: PASS

Artifact association: PASS

Machine-readable provenance: PASS

Provenance transport to Editor: FAIL

## Evidence

The Fool artifact produced:

    fool-task-001-144843.md
    fool-task-001-144843.provenance.yaml

The sidecar contained:

    artifact_id: fool-task-001-144843
    agent: fool
    environment: sandbox
    experiment: R0.5-001
    context_mode: clean
    epistemic_status: exploratory

However, Editor output contained no reference to:

- R0.5-001
- the artifact ID
- the provenance sidecar

The Editor's existing awareness of exploratory/sandbox status therefore
continues to originate from the embedded v0.4 report metadata, not from the
new first-class provenance object.

## Interpretation

Creating a provenance object is insufficient.

The provenance object must participate explicitly in the Council's
information topology.

## Architectural Requirement

Cognitive artifact transport must carry both:

    content
    +
    provenance

Downstream consumers must receive the provenance object associated with the
content they transform.

## Status
