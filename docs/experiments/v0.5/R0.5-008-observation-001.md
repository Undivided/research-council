# R0.5-008 Observation 001

## Source Observation

R0.5-007 proved that one process can safely resume an interrupted run.

The runtime preserves:

    original run ID
    completed successful outcomes
    promoted artifacts
    run-start execution inputs
    run-start epistemic context

and restarts only the interrupted agent.

## Remaining Race

Resume validation currently depends on durable state.

Two processes may inspect the same interrupted state close enough together that
both decide they are permitted to resume.

The durable state alone does not establish exclusive live ownership.

## Required Distinction

The next layer must distinguish:

    run is resumable

from:

    this process owns the right to resume it now

## Candidate Primitive

A kernel-backed exclusive advisory file lock is preferred over lock-file
existence.

A persistent lock pathname may remain after execution, but the operating system
determines whether the lock is currently held.

This avoids treating filesystem presence as proof of live ownership.

## Initial Scope

R0.5-008 should add concurrent-resumer exclusion only.

It should not introduce distributed coordination, automatic retries, or general
scheduling.
